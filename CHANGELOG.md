# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [v2.2.0] - 2026-09-01

### Added

- Extends UEFI credential rotation to DPUs with a dedicated convergence state that stages BIOS settings, restarts the DPU, and records the result one DPU per cycle, reusing the existing site-wide rotation flag and per-machine force override. ([#4462](https://github.com/NVIDIA/infra-controller/pull/4462))
- Extends routing-profile overrides, previously supported only on VPC creation, to VPC updates: each explicitly supplied override replaces the base-profile value while omitted properties keep inheriting from the profile. ([#4463](https://github.com/NVIDIA/infra-controller/pull/4463))
- Adds a `ListRackProfiles` RPC to the Rack API so clients can discover all configured rack profile IDs and definitions instead of only inspecting an existing rack's effective profile. ([#4425](https://github.com/NVIDIA/infra-controller/pull/4425))
- Persists the NVLink domain UUID reported by NMX-C for switches and exposes it through the NICo API, so switch health metrics and logs can identify failures at the cluster level. ([#4473](https://github.com/NVIDIA/infra-controller/pull/4473))
- Adds Helm chart support for materializing an external admin-client CA bundle into the site ConfigMap, so deployments with an existing user CA can populate `auth.adminRootCafilePath` without a manual step. ([#4423](https://github.com/NVIDIA/infra-controller/pull/4423))
- Adds a bmc-mock hardware profile simulating the NVIDIA GB300 N5700_LD NVLink switch tray, modeling its manager, system, chassis, network interfaces, sensors, assemblies, and firmware inventory from captured Redfish data. ([#4478](https://github.com/NVIDIA/infra-controller/pull/4478))
- Site Explorer now loads suppressed BMC MACs from the `suppressed_macs` table and skips them during exploration, preventing a machine being uningested or decommissioned from being re-ingested mid-teardown. ([#4143](https://github.com/NVIDIA/infra-controller/pull/4143))
- machine-a-tron can now simulate a WIWYNN GB200 NVL72 rack as a first-class atomic hardware model, rather than only its individual components, enabling full-rack registration and simulation testing. ([#4422](https://github.com/NVIDIA/infra-controller/pull/4422))
- Adds bounded admission control for Forge gRPC and admin HTTP requests: it limits executing and pending work before handlers touch the database, returns transport-appropriate overload responses, and also prevents stalled Scout streams from holding permits indefinitely. ([#4467](https://github.com/NVIDIA/infra-controller/pull/4467))
- Adds minimal support for OpenBMC-based Supermicro GB300 systems, bumping `libredfish` to v0.46.3 for the required platform support. ([#4121](https://github.com/NVIDIA/infra-controller/pull/4121))
- The site agent's BGP health report now includes IPv6-unicast address-family health, alongside the existing IPv4-unicast and EVPN checks, enabled once a DPU has its dedicated IPv6 loopback. ([#4314](https://github.com/NVIDIA/infra-controller/pull/4314))
- Exposes VPC routing-profile overrides (added in #4411 and #4463) through the REST API. See https://nvidia.github.io/infra-controller/ for the updated schema. ([#4502](https://github.com/NVIDIA/infra-controller/pull/4502))
- Switch telemetry now reads the NVLink domain UUID from NICo API switch inventory or static endpoint configuration and includes it in metric and log sink output, restarting collectors on UUID change so telemetry doesn't retain stale domain associations. ([#4476](https://github.com/NVIDIA/infra-controller/pull/4476))
- OTLP health report records now include per-alert detail (which component alerted and why) instead of only alert counts, since `convert_event` previously reduced `report.alerts` to its length. ([#4500](https://github.com/NVIDIA/infra-controller/pull/4500))
- Adds Core lifecycle APIs for tenant-managed SitePrefixes: new tenant roots are created in `Provisioning` and deletion is an idempotent transition to a retained `Deleting` state, keeping the CIDR and quota slot reserved. This does not yet make tenant roots allocatable or send them to a DPU. ([#4252](https://github.com/NVIDIA/infra-controller/pull/4252))
- Adds backend-agnostic component-manager support for resetting switch NVOS to factory defaults, with an RMS backend implementation that returns a job ID for progress tracking; bumps `librms` to v0.10.1. ([#4566](https://github.com/NVIDIA/infra-controller/pull/4566))
- The web UI can now manage a host's desired boot interface directly, with the exact selection and default-restoration controls previously only available through the older BMC-endpoint workflow. ([#4541](https://github.com/NVIDIA/infra-controller/pull/4541))
- Adds outcome-based metrics for static address assignment, removal, and preallocation operations: `carbide_static_address_assignments_total`, `carbide_static_address_removals_total`, and a preallocation counter. ([#3394](https://github.com/NVIDIA/infra-controller/pull/3394))
- Adds a Helm chart input for the DPU agent's machine-identity sign-proxy URL (already accepted by `AgentConfig` but not previously exposed by the chart), and lets each NICo DPF service supply an `extra_helm_values` table. ([#4563](https://github.com/NVIDIA/infra-controller/pull/4563))
- Adds a Tilt-based local development workflow for running NICo in a local kind cluster, giving developers a single entry point to start the Core stack, view resource status/logs, and rebuild individual images. ([#4531](https://github.com/NVIDIA/infra-controller/pull/4531))
- Adds `LifecycleState` to the Machine Metadata REST API model, exposing enhanced lifecycle state when metadata is requested. See https://nvidia.github.io/infra-controller/ for the updated schema. ([#4685](https://github.com/NVIDIA/infra-controller/pull/4685))
- Adds a generic Flow gRPC proxy to the REST API, reusing Core's existing `ExecuteCoreGRPC` proxy so a new Flow-backed REST endpoint no longer requires its own Temporal workflow, activity, typed request, and site-agent registration. ([#4560](https://github.com/NVIDIA/infra-controller/pull/4560))
- Extends machine-a-tron's rack simulation with a Lenovo GB300 NVL72 rack model: 18 Lenovo GB300 compute trays, 9 NVIDIA N5700 NVLink switch trays, and 6 LiteOn power shelves. ([#4530](https://github.com/NVIDIA/infra-controller/pull/4530))
- Adds an `instance-name` field to FMDS. ([#4675](https://github.com/NVIDIA/infra-controller/pull/4675))
- Adds NVIDIA OEM CSDL fields (via nv-redfish's OEM support) to hw-health's emitted metrics, with matching OEM field support added to bmc-mock. ([#4730](https://github.com/NVIDIA/infra-controller/pull/4730))
- VPC prefixes now retain which SitePrefix "parent" they matched at creation, instead of only checking containment and discarding the match, in preparation for tenant-managed SitePrefixes where retaining the parent matters. ([#4634](https://github.com/NVIDIA/infra-controller/pull/4634))
- Adds `nico-admin-cli site-prefix` commands to list/show SitePrefixes, create tenant-managed prefixes, replace their metadata, retire them, and inspect lifecycle history; exact-CIDR searches can return multiple results since SitePrefix IDs, not CIDRs, remain the identity. ([#4745](https://github.com/NVIDIA/infra-controller/pull/4745))
- Adds Helm support for configuring machine-a-tron atomic racks via `pods.<pod>.racks`; racks and machines render independently, so rack-only, machine-only, or combined simulations are all supported, and existing default machine behavior is unchanged when no rack configuration is supplied. ([#4721](https://github.com/NVIDIA/infra-controller/pull/4721))
