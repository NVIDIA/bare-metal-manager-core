🔒 DMZ Isolation — why DHCP does NOT leak to 10.17.48.0/24

① carbide-dhcp binds to specific interfaces only. The pod's --interfaces flag lists ens5 (VLAN 101) and ens8 (VLAN 201). No socket is ever opened on eth0 (DMZ). DHCP broadcasts arriving on the DMZ are silently ignored.
② MetalLB L2Advertisement is interface-pinned. l2-advert-vlan101 announces VIPs only on ens5; l2-advert-vlan201 only on ens8. VIPs 172.16.0.85–.95 and 172.16.10.85–.95 are never ARPed on eth0.
③ Switches relay DHCP — no broadcast crosses zones. The 10G switch has ip helper-address 172.16.0.85 on VLAN 101 interface only. The 400G switch has ip helper-address 172.16.10.85 on VLAN 201 interface only. DHCP unicast relay packets are routed; they never reach the DMZ subnet.
④ No default gateway from test VLANs to DMZ. 172.16.0.0/24 and 172.16.10.0/24 are isolated test segments with gateways 172.16.0.1 and 172.16.10.1 respectively — those gateways do not route to 10.17.48.0/24.

DHCP / PXE Boot Flow — per network path
⬜ BMC Boot Path — VLAN 101 (10G Switch)
1
SUT BMC powers on → broadcasts DHCP Discover on VLAN 101
2
10G Switch relays unicast to 172.16.0.85 (carbide-dhcp VIP)
3
carbide-dhcp → gRPC → carbide-api → allocates IP from 172.16.0.20–.60
4
DHCP Offer: IP + next-server=172.16.0.86 (carbide-pxe)
5
BMC fetches iPXE from 172.16.0.86:80 → boots Scout OS
6
Scout agent → mTLS/gRPC → 172.16.0.89:443 (carbide-api) → reports inventory
7
State: Discovering → Inventoried → Validated → Ready
DMZ is never involved. carbide-dhcp socket is on ens5 only. DHCP broadcasts stay on VLAN 101.
▣ DPU Boot Path — VLAN 201 (400G Switch)
1
SUT DPU powers on → broadcasts DHCP Discover on VLAN 201
2
400G Switch relays unicast to 172.16.10.85 (carbide-dhcp-dpu VIP)
3
carbide-dhcp-dpu → gRPC → carbide-api → allocates IP from 172.16.10.20–.60
4
DHCP Offer: IP + next-server=172.16.10.86 (carbide-pxe-dpu)
5
DPU fetches iPXE from 172.16.10.86:80 → boots DPU agent
6
DPU agent → mTLS/gRPC → 172.16.0.89:443 (carbide-api via VLAN101 cross-route)
7
State: DPU Attached → Provisioning → Ready
DMZ is never involved. carbide-dhcp-dpu socket is on ens8 only. DHCP broadcasts stay on VLAN 201.
